# <Product> — Function

> DEFINITION: what the product DOES and how it WORKS at the product level — its
>   capabilities, core user-facing flows, and intended behavior. The functional
>   spec of the should-be (not the implementation — that's the CTO repo).
> ROUTES HERE: descriptions of features, flows, behaviors, how a user moves through
>   the product, what it produces.
> GREP FOR: "what does product-N do?", "how is flow X supposed to behave?",
>   "what's the intended behavior of Y?"
> WRITE CLASS: auto for refinements; gated when a change redefines core behavior.
